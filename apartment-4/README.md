# آپارتمان چهارم — پلان دوبعدی و تور ۳۶۰

ورودی: ۴۰ عکس موبایل و یک ویدئوی ۷۳ ثانیه‌ای با توضیح صوتی از یک آپارتمان خالی.
خروجی: پلان دوبعدی تأییدشده (`plan.svg`) و تور ۳۶۰ با ۹ نقطه (`index.html`).

## روش

1. **پلان** — از روی گفتار ویدئو (ترتیب فضاها و جهت‌ها)، فریم‌های ویدئو (اتصال فضاها) و عکس‌ها (جزئیات) کشیده و با
   صاحب کار تأیید شد. همه‌چیز در `tools/plan.py` است.
2. **صحنهٔ سه‌بعدی ساده** — `tools/scene.py` همان پلان را به دیوار، در، پنجره، لنگهٔ در، کابینت و نقاط تور تبدیل می‌کند.
   راهنماها، داده‌های صفحه و متن دستور همه از همین فایل می‌آیند تا با هم اختلاف پیدا نکنند.
3. **رندر راهنما** — `tools/guides.py` از هر نقطه یک رندر سادهٔ ۳۶۰ می‌گیرد (پرتو از درهای باز رد می‌شود و اتاق بعدی
   را هم نشان می‌دهد) و فهرست «چه چیزی در کدام جهت است» را می‌نویسد.
4. **تبدیل به عکس** — `tools/render_pano.py` رندر راهنما و چند عکس واقعی همان فضا را به مدل تصویر می‌دهد تا فقط جنس و نور
   را واقعی کند و جای دیوارها را دست نزند.
5. **کنترل** — هر تصویر روی خطوط همان رندر انداخته و چشمی بررسی می‌شود؛ هرکدام خطا داشت دوباره ساخته می‌شود.

## اجرا

```
python3 tools/scene.py                      # home.js
python3 tools/guides.py GUIDES_DIR          # رندرهای راهنما
OPENROUTER_API_KEY=... python3 tools/render_pano.py N GUIDES_DIR PHOTOS_DIR panos/panoNN.jpg
python3 -m http.server 8000                 # سپس http://localhost:8000/index.html
python3 tools/build_standalone.py tour.html # یک فایل تکی که با دوبار کلیک باز می‌شود
```

## نکته‌ها

- ابعاد برآوردی است (کاشی حدود ۸۰ سانتی‌متر و اندازهٔ درها)؛ اندازه‌گیری واقعی در دست نبود.
- تصاویر ۳۶۰ با هوش مصنوعی ساخته شده‌اند، عکس ۳۶۰ واقعی نیستند؛ جزئیات ریز (جای کلید و پریز، رگه‌های سنگ) می‌تواند با
  واقعیت فرق کند.
- پوشهٔ `panos/` در مخزن نیست، چون مخزن عمومی است و این تصاویر داخل یک خانهٔ واقعی را نشان می‌دهند.
